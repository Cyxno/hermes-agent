## 3. Beacon (unraid-dashboard 1.3.18, GIT_SHA 2d56f22 == repo HEAD)

- Agent API v1: **GET-only** (getest: geen mutatie-routes), envelope `{apiVersion, beaconVersion, generatedAt, data}`, freshness `{sampledAt, stale, ageSeconds, source}`.
- Auth: `Authorization: Bearer $AGENT_API_TOKEN` (min 32 chars) of `AGENT_API_TRUST_LOCAL=true` (alleen als géén token; loopback/192.168.1.*; header-based, firewall is boundary).
- **Huidige status op deze host: DISABLED** — geen token geconfigureerd → alle endpoints 403 `{"error":{"code":"DISABLED"}}`. `openapi.json` is gedocumenteerd maar 404 in runtime. Issues-filter `?status=` gedocumenteerd maar niet geïmplementeerd.
- Endpoints (uit code geverifieerd, live alleen 403 getest): `/capabilities`, `/summary` (health/cpu/memory/storage/docker/thermal+episodes/actionCapabilities/automation/dependencies), `/docker` (containers met state/health/cpu/mem/update/managementType/risk/composeProject/provenance/freshness), `/issues` (id=`category:target:condition`, severity, status active/recovering/resolved, firstSeen/lastSeen/observedFor, suggestedChecks info-only; resolved 10 min retentie, cap 300), `/projects` (compose-grouping, services met risk), `/storage` (arrayState, parity, disks met temp), `/system`, `/operations`, `/events` (docker.transitions, in-memory 100), `/stream` (SSE: `hello` + `docker.transition` + `system.health`, ping 20s, ring 200, Last-Event-ID replay, **reconnect-cap 10/min**; rate-limits: summary 120/min, data 60/min, stream 10/min).
- Helper-container (`:8790`, loopback-only): enige component met docker.sock; levert inventory/updates/rollback-snapshots; voedt Agent API indirect.
- Sessies: Beacon heeft `audit.jsonl`, `automation-*`, `notifications-state.json` — Beacon doet zelf ook al incidentdetectie (issues). **Grens (§59)**: Beacon observeert/detecteert, Hermes interpreteert/escaleert/remedieert.

## 4. Netdata (v2.11.1) + Prometheus (v3.15)

- Netdata: host-net, :19999, **geen auth**, geen cloud-afhankelijkheid (claimed maar lokaal volledig), dbengine 14d/3mo/2y tiers, update 2s. 2434 charts. Per container (1117 cgroup-charts): `cgroup_<n>.cpu/.cpu_limit/.throttled/.throttled_duration/.mem/.mem_usage_limit/.mem_utilization/.io/.pgfaults/.pids_current/.writeback`. Host: `system.cpu` (dim `iowait`), `system.load`, `mem.available`, `mem.oom_kill`, `disk_await.<dev>` (ms/op, sda–sdg, md*), `disk_space/inodes.*`, `net_drops/net_errors.<iface>`, `docker_local.container_<n>_health_status/_state`, `mem.zram_*`.
- **Geen PSI en geen swap op deze host** (kernel/Unraid) — mag geen designedependency zijn.
- ML-anomaly: enabled (k-means, 6h train, 3h retrain, threshold 0.99): `anomaly_detection.anomaly_rate_on_<guid>`, `.dimensions_on_<guid>`, plus `options=anomaly-bit` per query.
- Alarms: `/api/v1/alarms` (1 actief: `docker_container_unhealthy` plexdb-ro, met hysteresis in `health.d/docker.conf`).
- Prometheus: targets cadvisor/homelab-exporter/node-exporter (15d retentie). cadvisor heeft `container_cpu_cfs_throttled_*` maar meeste containers hebben geen CPU-limit. Netdata is de rijkste bron voor throttling; netdata allmetrics kan als Prometheus-format (niet gescraped).
- Belangrijk voor v2: netdata alarm-API is een aanvulling, maar v2 pollt zelf charts (throttling/latency/anomaly) i.p.v. alleen alarm-mirroring.

## 6. Migratie-risico's (Phase A conclusies)

1. Repo/live-drift v1: vóór enige v1-wijziging eerst drift-repair, anders regresseert productie.
2. Beacon Agent API is uit: moet geactiveerd worden (token in template + recreate) vóórdat v2 Beacon als primary kan valideren.
3. DUMBscope is een permanenter vals-alarmgenerator in v1 (urgent + reminders op dode poort) — v2 verwijdert dit类别 volledig en demontreert noise-suppressie.
4. Geen PSI/swap: v2 mag hier niet op vertrouwen; gebruikt iowait/await/oom/anomaly als proxies.
5. `/mnt/cache/appdata/hermes/repo` (stale kopie) + stray files: cleanup-item in legacy-fase, niet eerder.
6. Netdata-anomaly-charts en Beacon thermal-episodes zijn nieuwe evidence-bronnen die v1 niet gebruikte.
