## 2. Waarom rc.2 (post-mortem rc.1)

rc.1 = `ghcr.io/cyxno/hermes-agent:2.0.0`, image `sha256:10776fd…`, git
`542c3a0` (docs-only verschil met HEAD ten tijde van de freeze-audit).

**Bug (correctness + crash/reliability + state-verlies):** `confirm_pattern`
(hermes/evaluator/incidents.py) gaf 12 bind-parameters mee aan een statement met
11 placeholders (`confirmed_at` had een letterlijke `NULL` in VALUES). Elke
pattern-bevestiging crashte daardoor de hele evaluatie-cycle en het pattern-
incident werd **nooit** naar SQLite weggeschreven (onzichtbaar weg bij restart).

**Bewijs:**
- 130× `cycle faalde — Incorrect number of bindings supplied (11 vs 12)` in de
  logs van rc.1, uitsluitend in het venster 2026-10-05 22:30 → 2026-10-06 04:34
  (local) — exact de periode waarin transient-episodes recurreerden (watchtower-
  flapping, beacon_unavailable:host). Van 04:34 tot de redeploy: 0 errors (de
  trigger was weg, de bug latent).
- Nieuwe regressietest faalde op rc.1-code met exact dezelfde foutmelding en
  slaagt na de fix.
- In de live DB stonden beide `transient_pattern:*`-rijen nog van vóór de
  rc.1-container: gedurende rc.1 is er geen enkel pattern-incident gepersisteerd.

**Fix:** placeholder toegevoegd (1 regel) + regressietest
`tests/test_transient_pattern_persistence.py`. Suite: **70/70 groen** (was 69/69).

**rc.1-loop-statistiek (voor het record, 21,4u):** 1396 cycli succesvol, 130
gefaald (~8,5%), 139 shadow-notificaties, 0 echte verzendingen, 0 AI-calls,
0 restarts, geen DB-corruptie (`integrity_check: ok`).

**Deploy-les:** bij het heraanmaken van de container was `BEACON_AGENT_API_TOKEN`
vrijgevallen uit de env-copy (401 op Beacon binnen 30 s). Hersteld vanuit de
container-inspect-backup (`.container-backup-rc1.json` in de repo-root).
Runbook-regel: bij een shadow-redeploy altijd de volledige env van de vorige
container klonen en alleen build-metadata (GIT_SHA/BUILD_TIME) vervangen.

## 3. Meting & rapportage

Dagelijks 06:00 (cron, `/boot/config/plugins/user.scripts/hermes-soak.cron` →
`tools/soak_daily.sh`): `tools/shadow_report.py` in een one-shot container met
host-reliability metrics (errors, gefaalde cycli, beacon/netdata-faalcycli,
SSE-disconnects, restarts, uptime). Output: `/mnt/user/appdata/hermes-v2/
data/reports/shadow-YYYY-MM-DD.md`. Read-only naar productie-data.

Per 24u vastgelegd: raw signals, unieke fingerprints, pending/confirmed/active/
resolved incidenten, suppressed transients, final-recheck cancellations, pattern-
incidenten, root/correlated incidenten, notification-worthy, v1-notificaties,
v2-hypothetische notificaties, executor would_execute/deny, AI Ling/DeepSeek
calls, errors + v1/v2 per dag en noise-reductie %.

Ieder relevant v1↔v2-verschil krijgt een classificatie: `V2_IMPROVEMENT`,
`V2_FALSE_POSITIVE`, `V2_FALSE_NEGATIVE`, `EXPECTED_ARCHITECTURAL_DIFFERENCE`,
`UNKNOWN_NEEDS_REVIEW` (UNKNOWN telt niet als correct).

Extra gates tijdens de soak (uit de fase-opdracht): false-negative hunting
(v1-log, Beacon-issue-historie, Netdata-alarmhistorie), temperature-policy
live bewijzen (600s sustain), load5 observeren, echte correlatie-episode
afwachten, Beacon/Netdata disagreement matrix, final-recheck-statistiek,
executor-dry-run-classificatie (elke UNSAFE_ACTION is cutover-blocker),
"los het op"-pad end-to-end testen, AI-routing release-gate test-only.

## 6. Soak-review rc.3 (2026-10-07) — drie correctness-bugs gevonden en gefixt

De rc.3-soak (19,9 uur, 1530 cycli, 0 restarts) voldeed operationeel, maar de
notificatie-analyse legde drie bugs bloot:

1. **Pattern-episode storm (blocker)**: `confirm_pattern` deed INSERT OR
   REPLACE bij heropening binnen het transient-venster en resette daarmee
   `notification_sent`/`last_notified_at`. Elke fling van plex-scraper-vfs
   (~4–14 min) werd opnieuw een "eerste" alert: 41 alerts in ~10 uur, waarvan
   28 duplicaten van hetzelfde pattern-incident. Fix: heropen dezelfde episode
   mét behouden notificatieboekhouding; pattern-incidenten volgen het
   transient-venster (tracker lost af bij venster leeg), niet het live-signaal.
2. **Recovery-notificaties structureel dood**: niemand produceerde ooit een
   `resolved`-intent; 0 herstelberichten ondanks `notify_recovery: true`.
   Fix: `_resolve` emit een resolved-intent na eerder verzonden alert; de
   pipeline draait de final recheck geïnverteerd (conditie weg = bevestiging,
   conditie terug = annulering); pattern-incidenten skippen de recheck.
3. **Cooldown-unit inconsistentie**: DEFAULTS en example documenteren minuten,
   de live config.yaml schreef seconden-cijfers (43200/86400) — met de `*60`
   in de code dus 30/60 dagen i.p.v. 12/24 uur. Fix: code houdt minuten aan
   (`*60` hersteld + gedocumenteerd), live config genormaliseerd naar minuten
   (identieke beoogde duurtijden; geen threshold-tuning).

Regressietests: `tests/test_pattern_episode_and_recovery.py` (4 scenario's).
Suite na fix: 76/76 groen, ruff clean.
